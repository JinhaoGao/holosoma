Robot-to-robot 重定向使用 `examples/robot2robot_retarget.py`。它读取一个机器人 CSV，通过源模型 FK 恢复语义关键点位置和朝向，再进入 human2robot 共用的预处理、Interaction Mesh 形变能、朝向目标、接触约束和 SQP 求解流程。FK 只还原源运动，目标关节角由优化器求解。输出同时包含目标 NPZ 和同名 CSV。

从 `src/holosoma_retargeting/holosoma_retargeting` 目录运行 `python examples/robot2robot_retarget.py --source-robot g1 --robot e2 --input-path /path/to/motion.csv --fps 50 --orientation-tracking True`。无界面运行增加 `--retargeter.no-visualize`。也可以从仓库根目录在配置好包路径的环境中运行 `python -m holosoma_retargeting.examples.robot2robot_retarget` 并传入相同参数。G1→E2 是首个测试用例；更换源、目标名称即可使用其他配置组合。维护的配置包含 G1、E1 23DoF、E1 24DoF 和 E2，`e1` 兼容名称解析为 `e1_23dof`。

CSV 与现有 `data_utils/npz_to_csv.py` 的输出一致：无表头，每行一帧，依次为根位置 xyz（米）、根四元数 xyzw、按源 URDF 文件中非固定关节顺序排列的关节值。旋转关节单位为弧度，移动关节单位为米，世界坐标采用右手 Z-up。必须提供正的有限 `--fps`，因为 CSV 不保存时间信息。程序不猜测外部列布局，也不根据自由度数量猜测关节名称。所有关节按名称映射到 MuJoCo 模型，根四元数转为内部 wxyz 并归一化；空文件、缺列、非有限数值和零四元数会在求解前报错。输入帧数和 FPS 保留。

每个机器人在 `examples/robot_profiles/<robot>.json` 的可选 `robot_motion` 部分描述自身，不维护源目标成对的配置。`position_links` 将语义关键点映射到模型 body 原点，`parents` 定义这些关键点的有根树，`root_joint` 指向实际浮动根 body，`toe_names` 按左、右顺序标记脚底前端点。`orientation_links` 为同一语义集合中的点指定朝向 body，因此位置锚点和朝向 body 可以不同。逐骨段模式还要求双方对应语义点的父子关系一致。可选 `robot_motion.position_scaling` 包含 `torso_link` 和 `torso_anchor_names`，前者为躯干刚体，后者为直接挂在语义根下的肩部等锚点。目标声明躯干锚点时，源也必须声明躯干刚体；程序用源躯干转动重建目标躯干锚点。内置机器人均已配置，未声明时根的直接子节点按根部刚体几何处理。源配置必须提供目标映射所需的语义名称；无法对应时直接报错，不静默丢弃目标。可通过模型中的固定辅助 body 定义额外锚点。

`reference_base_quaternion_wxyz` 与 `reference_joint_positions` 定义双方具有相同语义姿态、相同世界朝向的参考姿态；未列出的关节取零。公共求解器根据源、目标参考姿态 FK 计算固定 link 坐标系偏移，再将该偏移应用到逐帧源朝向。不能把任意两个机器人的机械零位直接当成匹配参考姿态。内置配置使用已有的机器人参考姿态；朝向保存采用现有紧凑诊断格式。`robot_motion.orientation_weights` 为目标语义朝向声明权重，通过原有 `--orientation-tracking True` 开启，`--orientation-weights` 可以统一覆盖。默认开关继续继承目标机器人表。

`robot_motion.robot_config` 指定目标的脚底 link、手动关节边界、关节代价和 nominal tracking 索引。`foot_contact_links` 为每侧声明脚跟两点、前脚掌两点及脚尖。源 FK 使用真实脚跟和脚尖坐标进入公共接触检测，避免套用人体踝关节估计脚跟的偏移；检测结果进入同一套目标足底约束。默认 `--position-scaling segment` 在公共求解之前按目标模型 FK 的逐骨段长度重建位置参考，保留源动作逐帧的肢段方向。骨盆宽度、躯干锚点和脚底几何采用目标尺寸；根部 XY 位移按双腿髋到踝链长之和的比例缩放，根部 Z 由重建后的腿和脚底决定。支撑阶段从原始源脚底检测，腾空时最低脚底离支撑基线的高度按腿长比例保留，基线在支撑帧之间插值，不逐帧把腾空动作压到地面。无支撑帧时以最低脚底高度的第 2 百分位估计基线。该处理针对平地 `robot_only`，不是台阶地形估计。朝向损失仍使用未经位置缩放的源 FK 朝向及双方参考姿态标定。需要旧的身高统一比例预处理时指定 `--position-scaling uniform`。`--foot-sticking True|False`、形变能、根部稳定、自然姿态及求解参数沿用现有接口。

新机器人通过 `--source-robot-profile FILE_OR_DIR` 或目标的 `--robot-profile FILE_OR_DIR` 接入，名称使用字符串，不需要修改脚本中的枚举或注册某个机器人对。提供完整机器人表、URDF 以及同目录同文件干名的 MuJoCo XML；两个模型必须描述同一组标量关节，MuJoCo 模型必须有一个位于 qpos 开头的浮动根。自定义模型路径建议写成绝对路径，相对路径按 retargeting 包目录解释。纯 robot2robot 自定义机器人可以把人体数据集的 `orientation.datasets` 设为空对象，朝向权重由 `robot_motion` 提供。当前公共求解器面向具有左右脚底定义的浮动基机器人，并不自动推断陌生机械结构的语义映射。

专用肩部方向项继续沿用现有实现。G1、E1、E2 使用已有的手臂链识别；其他模型可在 `robot_motion.robot_config.shoulder_direction_chains` 中按左、右顺序提供两份链定义，字段为 `shoulder_joint_names`（三个关节）、`torso_basis_link_name`、`shoulder_anchor_link_name`、`elbow_link_name`、`hand_link_name`、`elbow_joint_name` 和 `wrist_joint_names`（零至三个关节）。源语义名称需满足现有 Hips/Arm/ForeArm/Hand 或 Pelvis/Shoulder/Elbow/Wrist 骨架约定。通用位置和完整朝向重定向不要求开启该专用项。

默认结果为 `demo_results/<target>/robot_only/robot2robot/<source>/<motion>.npz` 和同目录的 `<motion>.csv`。`--save-dir` 修改结果根目录，`--output-name custom.npz` 同时确定两份输出的文件干名，`--overwrite` 重新求解并重新导出。已有兼容 NPZ 时沿用现有恢复机制，缺少 CSV 则直接补导出；配置不同会要求显式覆盖。NPZ 保留目标 qpos、FPS、实际映射点和朝向、Interaction Mesh、接触计划与诊断，并记录源机器人、源 URDF、输入关节顺序和目标 URDF。CSV 仅从最终 NPZ 导出，使用目标 URDF 关节顺序，因此可以作为下一次 robot2robot 的输入。

使用 `python viser_player.py --input-path <result.npz> --show-human-skeleton True --show-robot-skeleton True` 查看结果。参数名兼容现有播放器，机器人来源的参考图层显示为 Source robot skeleton；目标模型优先使用 NPZ 中记录的 URDF，支持未注册的自定义机器人名称。这里显示的是送入优化器的位置参考骨架；逐骨段模式下它已经采用目标机器人尺寸。原始源关键点另存为 `robot_motion_source_positions_world`，骨段长度、根位移比例、脚底参考和离地高度保存在 `body_proportion_*` 与 `root_translation_scale` 元数据中。

验证命令为 `PYTHONPATH=src/holosoma_retargeting:src/holosoma:src/holosoma_inference python -m pytest --confcutdir=tests tests/test_robot2robot_retargeting.py`，从仓库根目录、安装了 retargeting 依赖的环境运行。另运行 `tests/test_robot_proportions.py` 验证各段长度、方向、躯干宽度、脚底几何及腾空保留。专用测试覆盖内置模型的 CSV/FK 往返、已知根旋转、非法输入、G1→E2 与反向及 E1→E2 的真实优化、自定义源目标名称、参考姿态校准、双格式一致性和恢复行为。完整重定向回归使用 `tests/test_*.py`。`--confcutdir=tests` 隔离仓库根目录面向训练环境的 conftest，不改变重定向测试内容。测试动作是确定性的合成短序列，用户的实际 CSV 仍需进行动作质量验收。

公共 SQP 对 human2robot 和 robot2robot、首帧和后续帧统一采用收敛条件加硬上限。默认 `--sqp.max-iterations 100`；连续 `--sqp.stable-iterations 2` 次同时满足局部 QP 代价变化和优化 qpos 步长阈值才提前停止。代价条件为 `abs(cost_new-cost_old) <= cost_atol + cost_rtol * max(abs(cost_new), abs(cost_old))`，默认 `--sqp.cost-atol 1e-8`、`--sqp.cost-rtol 1e-5`；归一化且对齐根四元数符号后的优化 qpos 最大分量变化不得超过 `--sqp.step-tolerance 1e-4`。这是数值停止判据，不等价于全局最优或物理可执行性保证。达到硬上限仍未收敛的帧会告警并保存 `sqp_converged=False`、`sqp_stop_reasons=max_iterations`；正常停止为 `converged`。NPZ 同时保存每帧迭代数、最后步长和代价变化。只有一次迭代时，最后代价变化为正无穷，表示没有前一次代价可供比较。新策略参与结果配置校验，旧结果需 `--overwrite` 或更换输出名称后重算。
